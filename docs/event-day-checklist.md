# Лиза × Виктор — чек-лист дня мероприятия

Дата второго дня: **30.08.2026**

## 1. За 60–90 минут до гостей

- [ ] Открыть `/admin` на телефоне/ноутбуке владельца и войти owner-аккаунтом.
- [ ] В верхнем блоке `РЕПЕТИЦИЯ` проверить быстрые ссылки: `ОТКРЫТЬ ТВ`, `РЕГИСТРАЦИЯ ГОСТЯ`, `КВИЗ`, `MK`, `MK НА ТВ`.
- [ ] Открыть `/screen` на каждом ТВ/проекторе в полноэкранном режиме.
- [ ] На каждом ТВ один раз нажать `ВКЛЮЧИТЬ ЗВУК`.
- [ ] Убедиться в админке, что heartbeat видит все реальные экраны online.
- [ ] Проверить `ВИДЕО ГОТОВО` и `ЗВУК ГОТОВ` для премьеры.
- [ ] Проверить QR с реальной дистанции комнаты.
- [ ] На телефоне владельца проверить `/admin` в портретной ориентации: нет горизонтального скролла, основные кнопки доступны большим пальцем.
- [ ] На ТВ 1920×1080 проверить: QR/текст не обрезаны, браузер не увеличил масштаб страницы.
- [ ] Проверить интернет и питание всех устройств; отключить авто-сон ТВ/ноутбука.

## 2. Перед регистрацией

- [ ] Если до этого была репетиция — выполнить dangerous reset с подтверждением `СБРОСИТЬ`.
- [ ] После reset: гостей `0 / ~40`, регистрация открыта, следующий билет `LV-001`, MK/Bunker/quiz runtime очищены.
- [ ] Убедиться, что ответы Лизы/Виктора после reset **сохранились**.
- [ ] Проверить 5 вагонов: номер, название, визуальная марка, цвет.
- [ ] Зарегистрировать одного тестового гостя.
- [ ] Проверить: на телефоне появился билет; в `/admin` — гость и toast; на ТВ — настоящий поезд с именем пассажира и вагоном.
- [ ] Проверить, что поезд не перекрывает QR после окончания своей короткой сцены.
- [ ] Снова выполнить reset, если тестовый гость не должен остаться.

## 3. Регистрация и поздние гости

- [ ] Следить за счётчиком гостей в `/admin`.
- [ ] При дубле удалять только лишнюю регистрацию через подтверждение.
- [ ] Если гость сменил телефон — выдать recovery code и восстановить билет.
- [ ] Нажать `ЗАФИКСИРОВАТЬ СОСТАВ` в нужный момент.
- [ ] После фиксации **не закрывать регистрацию**: опоздавшие должны продолжать получать свободный вагон.
- [ ] Проверить одного позднего гостя после фиксации состава.
- [ ] После премьеры регистрация также должна продолжать работать.
- [ ] Если Realtime кратко потерялся, админка должна сама подхватить нового гостя резервным polling и не скрывать старый dashboard.

## 4. Вагоны и экранные события

- [ ] Отправить тестовый вызов одному вагону — баннер должен появиться на телефонах нужного вагона.
- [ ] Проверить вариант `ПОКАЗАТЬ НА ЭКРАНЕ` на ТВ.
- [ ] Очистить тестовый вызов.
- [ ] Убедиться, что вызов вагона визуально отличается от сцены прибытия поезда.
- [ ] Во время Premiere/MK/Bunker обычные регистрации и вызовы не должны перебивать защищённую сцену.

## 5. Квиз, пара и Final Five

- [ ] Активировать тестовый вопрос.
- [ ] Ответить минимум с двух гостевых телефонов.
- [ ] Проверить live-счётчики/проценты на ТВ.
- [ ] Показать результаты.
- [ ] Проверить reveal ответа пары.
- [ ] До reveal приватные ответы Лизы/Виктора не видны гостям.
- [ ] Проверить отдельные token-ссылки `/liza` и `/viktor` для Final Five.
- [ ] Убедиться, что роли/ответы не смешиваются и приватные значения не раскрываются раньше команды владельца.

## 6. Mortal Kombat

- [ ] Открыть регистрацию MK.
- [ ] Проверить вход из гостевого билета `MORTAL KOMBAT · УЧАСТВОВАТЬ`.
- [ ] 16-й игрок остаётся в основной сетке; 17-й попадает в waitlist.
- [ ] Проверить no-show: `УБРАТЬ ИЗ СЕТКИ` → поднять запасного → заново перемешать/расставить позиции.
- [ ] Зафиксировать сетку: должно быть 15 матчей.
- [ ] `ЗАПУСТИТЬ ТУРНИР` выводит MK на общий `/screen`.
- [ ] Выбрать текущий бой — общий ТВ показывает VS-сцену.
- [ ] `ВЫВЕСТИ СЕТКУ НА ЭКРАНЫ` показывает bracket вместо боя.
- [ ] `ВЕРНУТЬ ГЛАВНЫЙ ЭКРАН` освобождает общий `/screen`, **не останавливая сам турнир**.
- [ ] Отдельный `/mortal-kombat/screen` продолжает показывать MK независимо от общего ТВ.
- [ ] Проверить победителя → продвижение в следующий раунд.
- [ ] Проверить correction/undo с предупреждением о downstream-матчах.
- [ ] Проверить champion scene.
- [ ] Убедиться: MK не может забрать общий ТВ, пока активен Bunker или защищённая Premiere.

## 7. Premiere — preflight

- [ ] В админке сохранён production URL реального видео `КОЛЬЦО` и длительность около `623 сек`.
- [ ] Сам файл видео хранится **вне GitHub**.
- [ ] Каждый ТВ подтверждает реальный `canplay`.
- [ ] Каждый ТВ показывает `ЗВУК ГОТОВ`.
- [ ] Пока хотя бы один активный экран/video/audio не готов, `НАЧАТЬ ПРЕМЬЕРУ` disabled и показывает причину.
- [ ] Количество гостей само по себе не блокирует старт: готовность основной массы — рекомендация ведущему.
- [ ] Проверить `ПАУЗА`, `ПРОДОЛЖИТЬ`, `−5`, `+5`, `С НАЧАЛА`, `ЧЁРНЫЙ ЭКРАН`, `ГЛАВНЫЙ ЭКРАН`.

## 8. Premiere — запуск

- [ ] Запускать вручную, когда основная масса гостей приехала; не ждать абсолютно всех.
- [ ] Перед стартом визуально проверить оба ТВ.
- [ ] Отсчёт должен быть строго `10 → 9 → … → 2 → 1`, без `0`.
- [ ] Sound cue заметнее на `3–2–1`, без гудка поезда.
- [ ] Видео стартует после `1`.
- [ ] Второй/поздно открытый ТВ получает authoritative position, а не начинает ролик с нуля.
- [ ] Во время Premiere registration/train/call/quiz/MK не перекрывают видео и не звучат под ним.
- [ ] При естественном конце остаётся чёрный кадр до owner-команды.
- [ ] После `ГЛАВНЫЙ ЭКРАН` проверить QR/актуальный сценарий.
- [ ] Зарегистрировать позднего гостя после премьеры — он получает обычный новый билет, ранние назначения не меняются.

## 9. Бункер — сюжетный поворот

- [ ] В `/admin` открыть owner-dock `БУНКЕР`.
- [ ] Первый клик `ПОДГОТОВИТЬ ЭКСТРЕННОЕ СООБЩЕНИЕ` ничего не меняет на ТВ без второго подтверждения.
- [ ] Подтвердить `ЗАПУСТИТЬ ЭКСТРЕННОЕ СООБЩЕНИЕ · 30:00`.
- [ ] На всех ТВ: `ЭКСТРЕННОЕ СООБЩЕНИЕ` → `ПОЕЗД ИЗМЕНИЛ МАРШРУТ` → `БУНКЕР`.
- [ ] Два ТВ показывают один серверный таймер с расхождением не более примерно 1 секунды.
- [ ] Проверить alarm/autoplay fallback.
- [ ] Bunker снимает underlying Premiere/MK/quiz/train и гасит уже звучащий arrival cue.
- [ ] Запустить Bunker поверх тестовой Premiere: видео должно физически исчезнуть из DOM/экрана; после STOP идёт новый authoritative read.
- [ ] На `00:00` emergency **остаётся** как `ПРИБЫТИЕ · БУНКЕР / 00:00`; alarm прекращается.
- [ ] Возврат к обычному ТВ происходит только после `ОСТАНОВИТЬ БУНКЕР`.
- [ ] Проверить reset во время активного Bunker: emergency должен погаснуть и при потерянном broadcast за счёт polling.

## 10. Потеря сети

- [ ] На одном ТВ отключить Wi‑Fi на 10–20 секунд.
- [ ] Последнее безопасное состояние остаётся на экране; белого экрана нет.
- [ ] Появляется `СВЯЗЬ · ПЕРЕПОДКЛЮЧЕНИЕ`.
- [ ] Один восстановившийся источник не должен скрывать ошибку другого.
- [ ] После полного reconnect authoritative state перечитывается автоматически.
- [ ] Heartbeat отвалившегося ТВ исчезает примерно через TTL и возвращается после reconnect.
- [ ] В `/admin` временный background failure не должен выбрасывать владельца из панели: остаётся последний валидный dashboard + ненавязчивый reconnect status.

## 11. Прямо перед гостями

- [ ] Все тестовые гости очищены; следующий билет `LV-001`.
- [ ] Owner-сессия уже открыта на основном телефоне/ноутбуке.
- [ ] Пароль владельца доступен офлайн владельцу.
- [ ] `/admin` и `/screen` находятся на разных устройствах/окнах.
- [ ] Оба ТВ подключены к питанию, авто-сон отключён.
- [ ] Системная громкость и HDMI/audio output проверены.
- [ ] Реальный production-домен открывается с гостевого телефона без VPN/preview-ссылки.
- [ ] Ответы Лизы/Виктора реально заполнены в production-базе — не только создана пустая схема.

## Аварийный порядок

1. ТВ завис — **не делать reset базы**; обновить только `/screen`.
2. Звук не работает — нажать `ВКЛЮЧИТЬ ЗВУК`/fallback на конкретном ТВ и проверить системный output.
3. Один ТВ отстал по Premiere — обновить `/screen`; authoritative position должен восстановить синхронизацию.
4. Premiere пошла неправильно — `ПАУЗА` → при необходимости `С НАЧАЛА` или `ЧЁРНЫЙ ЭКРАН`.
5. Bunker запущен не вовремя — `ОСТАНОВИТЬ БУНКЕР`; не перезапускать `30:00` вслепую.
6. MK мешает основному экрану — `ВЕРНУТЬ ГЛАВНЫЙ ЭКРАН`; турнир при этом не теряется.
7. Админка показывает reconnect — не перезагружать команды многократно; дождаться восстановления или проверить сеть, сохраняя последний валидный state.
